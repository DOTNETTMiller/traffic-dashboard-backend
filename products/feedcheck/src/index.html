Clear checks. Clear limits.

A practical review aid for road-event feeds.

WHAT WE CHECK

Operational data hygiene

  • Missing, invalid, or duplicated record IDs
  • Missing road names and event classifications
  • Invalid timestamps, timezone omissions, and reversed date ranges
  • Feed and event age against your thresholds
  • Events beyond their end time and grace period
  • Geometry structure and coordinate ranges
WHAT A RESULT MEANS

Evidence for a conversation

Error: a structural or consistency issue that can prevent reliable use.

Warning: a missing field or operational condition that needs review.

“Without findings” means no event-level rules fired. Feed-level findings are shown separately. An empty feed never receives an all-clear conclusion.

SUPPORTED INPUT

Keep the first version focused

GeoJSON FeatureCollections; WZDx-style road events with properties.core_details; flat JSON event arrays or {"events":[…]}.

Generic fields: id/eventId, road/roadName/corridor, eventType/type, startDate/startTime, endDate/endTime, updated/lastUpdated, and GeoJSON geometry or numeric latitude/longitude.

WZDx-style input reads dates from event properties and update time from core details. Device feeds, XML, and custom vendor mappings are outside this edition.

PRIVACY & SCOPE

Local by design

No analytics, accounts, external libraries, or automatic storage. File and pasted data are processed in browser memory. URL checks contact only the feed URL you provide.

Exports contain source labels, findings, and record IDs. URL query strings and credentials are removed from report source labels. Review file names and labels before sharing.

This tool does not certify full WZDx/CWZ conformance, verify field accuracy, establish missing real-world events, or monitor feeds while closed.
