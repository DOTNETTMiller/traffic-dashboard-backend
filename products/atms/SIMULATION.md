# Simulated agency and acceptance exercises

The local training ATMS can operate without an agency or field partner. It includes
an external synthetic agency model, independent UDP sign controllers, an operator
scenario desk and six repeatable acceptance exercises. Passing an exercise does
not establish physical compatibility, national coverage, detection accuracy or
procurement eligibility.

## Open the scenario desk

Build with `npm --prefix frontend run build`, then run `npm run start:atms`.
The default is `http://127.0.0.1:4432/atms.html`. Choose **Simulated agency**.

- Select crash, work-zone, storm or clear conditions. Source conditions can
  disconnect the feed, empty its snapshot, duplicate an event or change geometry.
- Click **Import observations**, then review/promote the report in Source
  inbox. Import never assigns ownership, verifies an incident or resolves an
  existing operator record. An outage retains the last imported observations.
- In **Corridor**, select map assets to inspect their state, zoom the illustration,
  and inspect controller readbacks in the message-board panels.
- View the procedural camera illustration, pause its animation, change simulated presets or disconnect
  it. Optionally choose a local MP4/WebM traffic recording. Recordings remain in
  the browser and are not uploaded or included in reports. Presets do not control
  or transform a recorded clip.
- In **Response**, select an incident to assign a responder or notify the simulated duty desk.
  Delivery, dropped delivery and recipient acknowledgement are distinct states.
  These actions send nothing externally.
- Use Devices for the existing sign emulator's communication loss, local control,
  validation refusal, lost acknowledgement, mismatch, override and expiry controls.
  Inspect actual readback and resulting command states in Command log.

The corridor follows an offline snapshot of Iowa DOT RAMS All Routes directional
I-80/I-35 mainlines, with 873 retained vertices. A shared Mercator projection fits
the roads, simulated assets and affected segment without stretching the alignment.
The affected segment is sliced along the road; separate carriageways remain separate.
The map does not require external tiles or a routing service at runtime. Attribution,
retrieval date, query and processing method are retained in
`fixtures/des-moines-road-alignment.geojson`. Regenerate the snapshot with
`node scripts/atms-import-road-alignment.cjs` from the repository root.

The sign markers use explicit simulated placements along the matching route and
direction; these do not overwrite controller inventory coordinates. Cameras,
responders, CAD locations and source affected limits use the same reference roads.
Existing promoted incidents retain their old geometry until an operator reviews
and adopts a refreshed observation. Road reference data does not establish field
accuracy of a simulated device or event. The camera remains an illustration;
traffic and weather values are generated by the scene, not computed from video.
Agency configuration and recipient records persist in the training database.

## Automated acceptance

In **Exercises**, select **Run complete suite** or an individual exercise. Each uses a separate
temporary SQLite database and independent loopback controllers. Scripted operator,
incoming operator and supervisor identities exercise the actual core, dispatcher,
geometry, publisher and audit paths. They do not modify the interactive
workspace's incidents or signs. One automated job runs at a time.

| Exercise | Requirement | Expected outcome |
| --- | --- | --- |
| Crash response | SIM-01 | CAD geometry survives promotion; ordered closure follows observed blank displays. |
| Crash response | SIM-02 | Approved wording controls two signs; self-approval and viewer commands fail. |
| Crash response | SIM-03 | Responder accepts; delivered messages need acknowledgement; dropped messages cannot be acknowledged. |
| Uncertain delivery | SIM-04 | Fresh GET reconciles without resending; disconnection supplies no fresh confirmation; override invalidates certainty; controller expires its display. |
| Operator handoff | SIM-05 | Responsibility remains until named acceptance; wrong identities and stale versions fail. |
| Feed protection | SIM-06 | Pinned WZDx 4.2/CWZ 1.0 payloads validate; changed geometry and stale/expired observations withhold publication. |
| Service recovery | SIM-07 | SQLite reopens while controllers stay running; in-flight uncertainty reconciles without duplicate activation. |
| Source failure | SIM-08 | Outage retains timestamps; duplicate IDs are rejected; empty snapshot alarms without closing incidents. |
| Every exercise | SIM-09 | The retained operational audit chain verifies. |

These are local acceptance requirements, not agency certification identifiers.
They address buyer-wants categories including provenance, messaging, handoffs,
recovery and acceptance evidence. They do not cover all 99 procurement wants.

Review a completed run and download its JSON report. It includes requirement IDs,
assertion outcomes, wall duration, controlled scenario timestamps, commands,
independent controller snapshots/protocol traces, external model state, audit
records, limitations and a SHA-256 digest. The service checks the stored digest
before serving a report. Retain a trusted external copy to detect privileged
history replacement.

Interrupted jobs are marked interrupted on restart, never passed. Failures remain
visible. The desk shows 25 recent runs and retains up to 200 per training database.
Archive reports and use a new training database when the limit is reached.

```sh
npm run simulate:atms
npm run simulate:atms -- --exercise service-recovery --output /tmp/atms-recovery-new.json
npm run test:atms
```

The CLI writes a new timestamped report under
`products/atms/runtime/simulation-reports/`. Explicit existing paths are never
overwritten. Failed suites exit nonzero and still save evidence. Loopback UDP
sockets must be allowed. No external service credentials or device addresses
are used.

## Remaining proof

- Actual camera/VMS/PTZ, CAD/AVL, sensor and notification-provider adapters.
- Physical controller models/firmware, agency networks and witnessed commissioning.
- Complete host/process failure, backup restoration and infrastructure failover.
  Recovery here reopens the application database, not the operating system or
  controller process.
- Concurrent operator capacity and production service objectives. Local exercise
  durations are not enterprise performance benchmarks.
- Detection quality, authoritative/licensed sources, accessibility acceptance,
  security assurance and agency references.

Simulation routes are absent in live mode. Training evidence never sets physical
`verified` command status. Live signing and commissioning boundaries remain active.
